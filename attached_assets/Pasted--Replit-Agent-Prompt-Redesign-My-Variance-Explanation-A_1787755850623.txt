# Replit Agent Prompt — Redesign My Variance Explanation Assistant UI/UX

## Objective

Redesign and upgrade my existing **Variance Explanation Assistant** web app without breaking the current working functionality.

The app already exists and the core finance workflow is already built. I want you to improve the **user experience, information architecture, visual polish, and navigation** while preserving the current backend logic, AI analysis flow, database persistence, and existing routes wherever possible.

This is a **UI/UX + structural enhancement task**, not a rebuild from scratch.

---

## Product Context

This is a finance-focused web application that helps users analyze **forecast vs actual variance**, generate structured AI-assisted explanations, and review historical analyses.

The current version works, but:

* the landing/new analysis experience feels too plain
* the result presentation is too basic
* navigation is limited
* the first screen should feel more welcoming and product-like
* the app should better support **Indian accounting and reporting conventions**

I want the upgraded product to feel like a polished, professional finance SaaS tool.

---

## High-Level Goal

Transform the current experience into a product with:

1. a **welcoming landing page**
2. a clear choice between:

   * **Manual Figure Entry**
   * **Upload Workbook**
3. improved navigation using a **left sidebar**, inspired by the productivity and project-list style of ChatGPT
4. a more polished and structured **results presentation**
5. visual design enhancements including a subtle **animated aesthetic background**
6. support for **Indian accounting usability standards**, especially for currency and number formatting

---

## Important Constraints

* Preserve the current working finance analysis logic.
* Preserve the current AI integration and do not remove the logic-before-AI workflow.
* Preserve database persistence.
* Do not break history or saved reports.
* Reuse the existing stack and current project structure as much as possible.
* Focus on UX, layout, navigation, and presentation quality.
* If route changes are needed, implement them cleanly and update navigation accordingly.
* Do not redesign into a chatbot UI.
* Keep the design professional, elegant, and finance-oriented.

# 6. Indian Accounting / Indian Usability Support

Adapt the app so it feels feasible and appropriate for users working in India.

This does not require building a full Indian compliance engine. It means the app should support common Indian finance/reporting conventions in the UI and data presentation.

## Required India-Focused Enhancements

### Currency and Number Formatting

Use Indian formatting conventions where appropriate:

* default currency should support **INR (₹)**
* format values using **Indian numbering style**

  * e.g. 1,00,000
  * 10,50,000
  * 1,25,00,000

Use `en-IN` locale formatting where possible.

### Period / Reporting Support

Support labels commonly used in Indian reporting:

* Month
* Quarter
* Financial Year (FY)
* Example: FY 2025–26

### Date Format

Prefer Indian-friendly date formatting such as:

* DD/MM/YYYY

### Terminology

Use professional finance wording suitable for India-based accounting/reporting users.

Examples:

* Financial Year
* Ledger / General Ledger
* Actuals
* Budget / Forecast
* Variance
* Cost Centre (optional if relevant)
* Department / Business Unit

### Flexible Category Handling

Keep category naming flexible so users can input categories commonly used in Indian accounting/reporting such as:

* Sales
* COGS
* Employee Benefit Expense
* Rent
* Professional Fees
* GST-related items if manually entered
* Admin Expenses
* Other Income

### Important Limitation

Do not claim statutory or audit compliance unless actually implemented.
Support Indian formatting and accounting usability, but do not falsely claim formal compliance certification.
